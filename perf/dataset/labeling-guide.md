# Gold 질의 라벨링 가이드

S 데이터셋(100개)은 `generate_dataset.py`가 파라미터를 직접 정답으로 삼아 자동 생성한다 — 이 단계는 사람 라벨링이 필요 없다(평가 파이프라인 자체를 검증하는 용도).

M(1,000개) 이상으로 확장할 때, 실제 포트폴리오 수치에 쓸 gold set은 아래 기준을 따른다.

## 절차

1. `generate_dataset.py`로 문서와 1차 후보 질의를 생성한다.
2. 질의마다 다음을 **사람이 직접** 원문에서 확인한다.
   - `relevant_sources`가 실제로 그 사실을 담고 있는 문서가 맞는지
   - `expected_facts`가 문서 원문과 정확히 일치하는지(패러프레이즈 아님)
   - 질문이 실제로 그 문서만으로 답할 수 있는지(다른 문서와 헷갈리지 않는지)
3. 1인이 작성했다면, 최소 전체의 20%는 다른 사람(또는 작성자 본인이 시간을 두고)이 2차 검토한다.
4. 검토 후 수정한 질의는 `query_id`를 유지하고 내용만 갱신한다(재현성을 위해 ID 체계는 안 바꿈).

## 하지 말 것

- 질문 생성 프롬프트에 평가용 질문을 그대로 노출하지 않는다(모델이 답을 외워서 맞히는 걸 방지).
- LLM에게 "이 문서의 정답이 뭐야?"라고 물어서 그 답을 그대로 gold로 채택하지 않는다.
- 검색 결과나 현재 애플리케이션의 실제 답변을 보고 나서 gold를 사후에 끼워 맞추지 않는다(먼저 문서를 보고 정답을 정한 뒤 애플리케이션을 테스트해야 함).
