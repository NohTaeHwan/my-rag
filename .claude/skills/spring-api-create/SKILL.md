# Spring API Create

## 개요

기존 프로젝트 구조를 먼저 확인하고 새로운 Spring MVC REST API를 구현한다. 프로젝트 루트의 `CLAUDE.md`에 적힌 규칙과 문서 경로를 따른다.

## 사용 시점

다음 요청에 사용한다.

- 새 HTTP 경로 또는 메서드 추가
- 기존 도메인에 새로운 REST API 동작 추가
- 새 요청·응답 모델과 Service 동작이 필요한 API 추가

다음 요청에는 사용하지 않는다.

- 코드를 바꾸지 않는 설명·조사
- 기존 API의 동작이나 요청·응답 구조만 변경
- API 제거·폐기
- 배포, README 오탈자, API와 무관한 설정 변경
- WebFlux, Kotlin, GraphQL, R2DBC 중심 작업

## 작업 순서

### 1. 신규 API 범위 확정

임시 검증용 API에도 기존 프로젝트 규칙과 문서 작성 기준을 동일하게 적용한다. API를 문서에 남기지 않거나 명세 업데이트를 생략하려면 구현 전에 사용자 승인을 받는다.

다음을 구현 전에 확정한다.

- HTTP 메서드와 경로, 기존 경로와의 충돌 여부
- 인증·인가 필요 여부
- 요청 파라미터·본문과 검증 조건
- 정상 응답과 실패 상태
- 데이터 없음, 중복 요청, 경계값 처리
- 기존 API와 호출부에 미치는 영향

불명확한 항목이 구현 방식에 영향을 주면 임의로 정하지 않고 사용자에게 확인한다.

완료 기준: 어떤 요청에 어떤 응답을 반환하고, 어떤 Controller·Service·데이터 접근 코드를 수정할지 설명할 수 있다.

### 2. 실패하는 테스트 작성(RED)

기존 테스트 방식에 맞춰 Controller 요청부터 Service 처리까지 이어지는 가장 작은 동작 하나를 테스트로 작성한다.

- Controller 테스트: 새 경로, 요청, 상태, 응답
- Service 테스트: 핵심 비즈니스 규칙과 데이터 접근 결과
- 인증이 있으면 허용·거부 경계

테스트를 실행해 미구현 동작 때문에 실패하는지 확인한다. 기존 구현 없이 통과하면 새 동작을 실제로 검증하는 테스트인지 수정한다.

완료 기준: 실패 출력과 실패 이유가 새 API 미구현임을 확인했다.

### 3. 최소 구현으로 테스트 통과(GREEN)

실패 테스트를 통과시키는 데 필요한 코드만 추가한다. Controller에서 Service와 기존 데이터 접근 구조까지 한 흐름을 완성한 뒤, 정상·실패·경계 동작별로 실패하는 테스트 작성(RED)과 최소 구현으로 테스트 통과(GREEN)를 반복한다.

새 추상화, 라이브러리, 공통 응답 형식, 예외 체계를 임의로 만들지 않는다.

완료 기준: 요구한 동작을 직접 검증하는 관련 테스트가 통과하고 기존 구조와 다른 불필요한 패턴이 없다.

### 4. API 명세와 관련 문서 업데이트·최종 확인

프로젝트에서 OpenAPI 명세나 관련 문서를 관리하고 있다면 API 변경 내용을 함께 반영한다. 마지막 코드 변경 이후 관련 테스트 결과를 확인하고, Stop Hook이 확인할 범위와 Claude가 직접 확인한 범위를 구분해 보고한다.

완료 기준: 수정 파일, 실제 테스트 결과, 업데이트한 명세·문서, 확인하지 못한 범위가 모두 보고됐다.

## 주의할 점

- 프로젝트 규칙을 읽기 전에 새 패턴부터 만드는 것
- Controller 성공 경로만 테스트하고 Service 실패·경계값을 빠뜨리는 것
- OpenAPI가 없는 프로젝트에 관련 의존성이나 파일을 추가하는 것
- Hook이 실행된다는 이유로 구현 전 테스트 실패와 구현 후 테스트 통과 확인을 생략하는 것
- 신규 API와 무관한 리팩터링을 함께 수행하는 것

- [ ] 기존 요청→데이터 접근 흐름과 테스트 패턴을 조사했다.
- [ ] 신규 경로·요청·응답·실패 동작을 확정했다.
- [ ] 구현 전에 작성한 테스트가 예상한 이유로 실패하는지 확인했다(RED).
- [ ] 필요한 코드만 구현한 뒤 테스트가 통과하는지 확인했다(GREEN).
- [ ] 정상·실패·경계 동작을 테스트했다.
- [ ] 프로젝트에서 관리 중인 API 명세와 관련 문서에 변경 내용을 반영했다.
- [ ] 실제 검증 결과와 한계를 보고했다.
