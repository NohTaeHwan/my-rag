# Spring API Update

## 개요

기존 API가 어떻게 동작하고 어디에서 사용되는지 먼저 확인한다. API 변경이 기존 사용처에 미치는 영향과 전환 방법을 구현 전에 정한다.

## 사용 시점

다음 요청에 사용한다.

- 기존 API 경로 또는 HTTP 메서드 변경
- 요청 파라미터·본문·검증 규칙 변경
- 응답 필드·상태 또는 비즈니스 동작 변경
- 새 endpoint로 기존 endpoint를 대체하는 혼합 변경

다음 요청에는 사용하지 않는다.

- 독립적인 신규 API만 추가
- API 제거·폐기만 수행
- 코드를 바꾸지 않는 설명·조사
- API와 무관한 리팩터링, 배포, 문서 오탈자 수정
- WebFlux, Kotlin, GraphQL, R2DBC 중심 작업

## 작업 순서

### 1. 기존 동작과 영향 범위 확인

기존 Controller, Service, 데이터 접근 코드, 테스트, 호출자, 명세를 추적한다. 다음을 구분한다.

- 반드시 유지할 기존 동작
- 이번에 바꿀 동작
- 영향을 받는 내부·외부 호출부
- 요청·응답 구조나 상태 코드 변경이 기존 호출부에 미치는 영향

완료 기준: 변경 전 호출 흐름과 영향을 받는 사용처를 설명할 수 있다.

### 2. 기존 사용처에 미치는 영향과 전환 방법 확인

경로·메서드·필수 필드·응답 필드·상태 코드 변경이 기존 호출자에 미치는 영향을 확인한다. 기존 호출 방식을 유지하기 어렵다면 다음 내용을 제시하고 사용자 판단을 받는다.

- 영향받는 호출부
- 기존 API 경로를 함께 유지할지 여부
- 병행 경로 또는 전환 방식
- 문서와 클라이언트 변경 범위

완료 기준: 기존 호출 방식을 유지할지, 승인받은 방법으로 전환할지 정해졌다.

### 3. 기존 동작 확인 및 실패하는 테스트 작성(RED)

먼저 유지해야 할 기존 동작의 테스트가 통과하는지 확인한다. 테스트가 부족하면 현재 동작을 확인할 수 있는 테스트를 추가한다. 그다음 변경할 동작의 테스트를 작성해 현재 코드에서 예상한 이유로 실패하는지 확인한다.

기존 기능이 깨지지 않았는지 확인하는 테스트와 새 동작 테스트를 한 번에 넓게 작성하지 않는다. 가장 작은 동작 단위로 실패하는 테스트 작성(RED)과 최소 구현으로 테스트 통과(GREEN)를 반복한다.

완료 기준: 유지할 동작의 테스트가 통과하고, 변경할 동작의 테스트는 예상한 이유로 실패한다.

### 4. 최소 구현으로 테스트 통과(GREEN) 및 기존 기능 확인

실패 테스트를 통과시키는 최소 범위만 수정한다. 공통 타입이나 공개 메서드를 바꾸면 전체 사용처를 다시 확인한다. 요청 밖 리팩터링은 분리한다.

완료 기준: 새 동작 테스트와 기존 기능을 확인하는 테스트가 모두 통과한다.

### 5. API 명세와 관련 문서 업데이트·최종 확인

프로젝트에서 관리 중인 API 명세와 관련 문서에 변경 내용을 반영한다. 변경 전후의 동작, 기존 사용처에 미치는 영향, 실제 실행한 테스트와 확인하지 못한 호출부를 최종 보고한다.

완료 기준: 수정한 코드, 테스트 결과, API 명세와 관련 문서가 같은 변경 내용을 설명한다.

## 주의할 점

- 기존 동작을 테스트로 확인하지 않고 바로 구현을 바꾸는 것
- 같은 저장소의 호출자만 보고 외부 공개 API 영향이 없다고 단정하는 것
- 응답 필드를 추가해도 기존 클라이언트에 영향이 없다고 단정하는 것
- 새 endpoint 대체 작업에서 기존 endpoint 유지·폐기 기준을 누락하는 것
- 컴파일이 통과했다는 이유만으로 기존 기능에 문제가 없다고 판단하는 것

## 완료 확인

- [ ] 현재 API 흐름과 호출자를 조사했다.
- [ ] 유지할 동작과 변경할 동작을 분리했다.
- [ ] 기존 호출 방식을 유지할지, 승인된 방법으로 전환할지 확인했다.
- [ ] 유지해야 할 기존 동작의 테스트가 통과하는지 확인했다.
- [ ] 변경할 동작의 테스트가 예상한 이유로 실패하는지 확인했다(RED).
- [ ] 필요한 코드만 수정한 뒤 관련 테스트가 통과하는지 확인했다(GREEN).
- [ ] 프로젝트에서 관리 중인 API 명세와 관련 문서에 변경 내용을 반영했다.
- [ ] 변경 전후의 동작과 확인하지 못한 범위를 보고했다.
