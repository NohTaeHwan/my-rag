# Spring API Delete

## 개요

공개 API를 어디에서 사용하는지 먼저 확인하고, 삭제 후 예상한 응답이 나오는지 테스트한다. 해당 API에서만 사용하는 코드만 제거하며, API 삭제를 DB 데이터·스키마 삭제 승인으로 간주하지 않는다.

## 사용 시점

다음 요청에 사용한다.

- 기존 endpoint 완전 제거
- endpoint를 폐기 상태로 전환
- 대체 API 전환 후 구 경로 정리

다음 요청에는 사용하지 않는다.

- 테이블 데이터·파일만 삭제
- 독립적인 신규 API 추가
- 기존 API의 동작만 변경
- 코드를 바꾸지 않는 설명·조사
- API와 무관한 리팩터링이나 배포
- WebFlux, Kotlin, GraphQL, R2DBC 중심 작업

## 작업 순서

### 1. 사용처와 삭제 범위 조사

API 경로(endpoint)에서 Controller, Service, 데이터 접근 코드까지 추적하고 다음 사용처를 찾는다.

- 내부 코드와 테스트
- OpenAPI 또는 다른 API 명세
- 같은 저장소의 클라이언트·문서·예제
- 배치, 이벤트, 외부 호출이 공유하는 Service·데이터 접근 코드

완료 기준: API 전용 코드와 다른 기능이 공유하는 코드를 구분했다.

### 2. 삭제 방식과 영향 범위 확인

API 경로를 완전히 제거할지, 기존 경로에서 410 응답이나 대체 API 안내를 반환할지 정한다. 공개 API 삭제, 인증 범위 변경, DB 컬럼·테이블·데이터 삭제가 포함되면 코드 수정 전에 사용자 승인을 받는다.

DB 변경은 API 삭제와 별도 범위로 취급한다. 명시적 승인이 없으면 수행하지 않는다.

완료 기준: 삭제 후 기대 HTTP 동작과 보존할 코드·데이터 범위가 정해졌다.

### 3. 삭제 후 동작을 확인할 실패 테스트 작성(RED)

프로젝트 표준에 맞춰 삭제 후 기대 동작을 테스트로 작성한다.

- 완전 제거: API 경로가 존재하지 않아 표준 404 응답
- 폐기 전환: 승인된 410, 경고 또는 대체 경로 안내
- 다른 API가 공유하는 Service 기능: 삭제 후에도 계속 동작

기존 endpoint가 남아 있기 때문에 테스트가 예상대로 실패하는지 확인한다.

완료 기준: 삭제할 API가 아직 존재하기 때문에 테스트가 예상한 이유로 실패하고, 다른 API가 계속 사용해야 하는 Service 기능을 확인했다.

### 4. API 전용 코드 제거 후 테스트 통과(GREEN)

Controller의 API 경로부터 제거하고 사용처를 다시 확인한다. 해당 API에서만 사용하는 것으로 확인된 DTO, Service 메서드와 데이터 접근 메서드만 정리한다. 컴파일 오류를 따라가며 공유 코드를 무차별 삭제하지 않는다.

완료 기준: 삭제 후 동작 테스트와 보존 대상 회귀 테스트가 통과한다.

### 5. API 명세와 관련 문서 업데이트·최종 확인

프로젝트에서 OpenAPI 또는 다른 API 명세를 관리하고 있다면 제거 또는 폐기 내용을 반영한다. 삭제한 파일, 유지한 공유 코드, 승인 없이 변경하지 않은 DB 범위와 실제 테스트 결과를 보고한다.

완료 기준: 코드, API 명세와 관련 문서에 같은 제거 내용이 반영됐고 남은 참조가 없다.

## 주의할 점

- API 경로부터 지운 뒤 컴파일 오류가 나는 코드를 전부 삭제하는 것
- API 삭제를 테이블·컬럼·데이터 삭제 승인으로 확대하는 것
- 같은 저장소에서 검색 결과가 없다는 이유로 외부 사용자가 없다고 단정하는 것
- 삭제 후 404·410 동작을 테스트하지 않는 것
- 공유 Service나 데이터 접근 코드를 API 전용으로 오인하는 것

## 완료 확인

- [ ] 내부·문서·테스트 사용처를 조사했다.
- [ ] API 전용 코드와 공유 코드를 구분했다.
- [ ] 기존 사용처에 미치는 영향을 확인하고 삭제 또는 폐기 방식을 승인받았다.
- [ ] DB 삭제는 별도 승인 범위로 분리했다.
- [ ] 삭제 후 동작을 확인하는 테스트가 예상한 이유로 실패하는지 확인했다(RED).
- [ ] API 전용 코드만 제거한 뒤 관련 테스트가 통과하는지 확인했다(GREEN).
- [ ] 다른 API가 공유하는 기능의 테스트가 통과하는지 확인했다.
- [ ] API 명세·관련 문서·남은 참조를 정리하고 결과를 보고했다.
